### [#1611 fix(tools): require a configured provider before registering generate_image](https://github.com/allenhutchison/obsidian-gemini/pull/1611)

The `generate_image` tool was registered whenever `imageGen` was routed to a provider, even with no key configured, so the model was offered a tool that could only answer "Image generation service not available". Registration is now gated on the same `featureStatus` check that builds the image service, so the two cannot drift apart. Two regression tests were added, and `provider-capabilities.md` and `agent-mode.md` now say routing plus a configured key is required.

### [#1610 fix: clear eslint-disables that fail the Obsidian plugin audit](https://github.com/allenhutchison/obsidian-gemini/pull/1610)

The 4.12.0 directory audit rejected inline disables for a fixed list of rules. This PR fixes each violation in code (destructive-button API, `ToolResult.data` typed `unknown`, `plugin.agentView` as a getter over workspace leaves, DOM-node progress rendering, class-based iOS layout fix, window timers, a desktop-guarded `http` import) and restores the full `no-restricted-disable` list in `eslint.config.mjs`, which had been trimmed so local lint allowed what the audit forbids. The deprecated `execCommand` paste fallback was removed. `AGENTS.md` documents the new policy.
