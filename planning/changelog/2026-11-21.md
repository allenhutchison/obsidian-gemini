## Summary

This was the busy day before the 4.14.0 release. The biggest change is #1777: the Ollama model picker now shows local and Ollama Cloud models together, and each request goes to the endpoint that serves the chosen model. #1778 adds the 4.14.0 release notes and fixes a deep research bug where the run saved an empty report and reported success. A dev-dependency bump (#1775) moved `@google/genai` to 3.x. That needed a quick follow-up (#1776) to keep Gemini requests on the `v1beta` API. The rest of the day was two Dependabot bumps, a translation refresh, and two daily-update PRs.

### [#1776 fix(gemini): pin API version to v1beta for @google/genai 3.x](https://github.com/allenhutchison/obsidian-gemini/pull/1776)

A follow-up to #1775. `@google/genai` 3.x changed its default Gemini Developer API version from `v1beta` to `v1`. The plugin's default `-latest` model aliases are only served on `v1beta`, so Gemini requests could fail. A `GEMINI_API_VERSION = 'v1beta'` constant is now passed from `createGoogleGenAI` and from `GeminiClient`'s no-plugin fallback, with tests for both paths.

### [#1777 feat(ollama): list local and Ollama Cloud models together](https://github.com/allenhutchison/obsidian-gemini/pull/1777)

A follow-up to #1765. With an Ollama API key and a local or custom base URL set, the model picker shows models from both sources, labelled `(local)` or `(cloud)`. Cloud models are stored as `cloud::<model>`, so the stored id alone decides where a request goes. `OllamaModelsService` fetches both model lists in parallel. If one source fails, it still shows the other and fetches again after 30 seconds. `OllamaClient` keeps one SDK client per endpoint. The docs were updated in `docs/guide/ollama-setup.md`, the settings and provider-capabilities references, and the README.

### [#1778 4.14.0 release notes and deep research empty-report fix](https://github.com/allenhutchison/obsidian-gemini/pull/1778)

This adds the `4.14.0` entry to `src/release-notes.json` and a "What's New in v4.14.0" section to the README. The version bump itself comes later. It also fixes the deep research bug found in pre-release testing (#1779). With Semantic Search on, the default `both` scope ran vault-only, because web search was no longer added once a file-search tool was set. Web search is now turned on for every scope except `vault_only`. A completed run with no report text now fails instead of saving an empty note. `docs/guide/deep-research.md` has a new troubleshooting entry for that error.
