### [#1281 fix(ollama): resolve context window per model, flag cloud-hosted models](https://github.com/allenhutchison/obsidian-gemini/pull/1281)

Three related Ollama gaps found by inspection while investigating why Ollama Cloud models never appeared in the model picker. The context window shown for an Ollama model was a flat 32k regardless of the model actually loaded; it's now resolved per model in priority order — the daemon's live `/api/ps` runtime allocation first, then `/api/show`'s trained ceiling, falling back to the 32k default only when the daemon is unreachable. Preferring the runtime allocation matters because Ollama sizes the window from available VRAM, so trusting a model's advertised ceiling could mean the plugin never triggers compaction while the daemon silently truncates the prompt. Separately, Ollama Cloud models — detected via the `remote_host` field rather than the unreliable tag naming — no longer claim to run entirely on-device: selecting one now replaces the "Everything runs on your machine" reassurance with a notice naming the model and host, since cloud models proxy inference (including note content) to ollama.com. Docs gained a "set the context window first" setup step, a cloud-models section, and a symptom-first FAQ entry for the failure mode this fixes.
