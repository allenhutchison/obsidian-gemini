## Summary

Alongside that, the loop detector's first fire finally surfaces as a user-visible notice instead of staying silent until the abort threshold, and a batch of turn-path and provider-client strings were routed through the i18n layer. ### [#1534 refactor(api): share one SDK APIError log formatter across provider clients](https://github.com/allenhutchison/obsidian-gemini/pull/1534)

The `audit-architecture` sweep flagged a DRY violation: the OpenAI and Anthropic clients each carried a private `describeError()` that flattened an SDK `APIError` into a log-friendly string, with the same eight lines duplicated under different field names. The shared version now lives as `describeSdkApiError()` in `src/utils/error-utils.ts`; both clients' existing log output is unchanged, but each gains a bit more detail (request id, or the response body's message) it couldn't previously carry.

### [#1537 fix: surface first loop-detector fire as user notice](https://github.com/allenhutchison/obsidian-gemini/pull/1537)

Fixes #1500. The `toolLoopDetected` event had no subscriber, so the first two fires of a runaway tool loop were invisible outside debug mode — only the abort notice at the third fire was visible. A new `LoopDetectionSubscriber` shows a transient notice on the first fire per session, then stays quiet so it doesn't stack with the abort notice.

### [#1533 chore(i18n): Update UI translations](https://github.com/allenhutchison/obsidian-gemini/pull/1533)

Automated regeneration of `src/i18n/` from the current English source strings.

### [#1539 refactor(services): own the state-folder layout in one leaf module](https://github.com/allenhutchison/obsidian-gemini/pull/1539)

Fixes #1382. The plugin's state-folder layout existed in three parallel forms — a folder-initializer constant list, several per-module private constants, and ~20 inline path literals — that had already drifted (a missing folder in the creator's list, a folder created twice, two UI sites skipping path normalization). A new `src/services/state-folder.ts` leaf module is now the single source of truth; every consumer was converted to it, and composed paths are byte-identical everywhere except the two previously un-normalized UI sites.

### [#1538 refactor(api): share one tool-id ledger across OpenAI and Anthropic clients](https://github.com/allenhutchison/obsidian-gemini/pull/1538)

Fixes #1535. The tool-call/tool-result id pairing policy was implemented twice, once per provider client, and had diverged on id validation, unmatched-response handling, and part ordering. The policy is now one leaf module (`src/api/providers/tool-id-ledger.ts`), parameterized by what actually differs per provider (id format, id validity pattern). Three resolved behavioral forks are called out in the PR: both providers now validate inbound ids, an unmatched response reports no-match instead of minting a stray id, and both resolve ids in the same source-part order.

### [#1541 i18n: route turn-path and provider-client messages through t()](https://github.com/allenhutchison/obsidian-gemini/pull/1541)
