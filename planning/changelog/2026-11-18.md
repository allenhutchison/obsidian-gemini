## Summary

A small maintenance day. The advisory `check:fields` scanner now looks inside nested object types, and the PR that did it also removed the unread fields the wider scan found. An Ollama follow-up closes a short-lived cache gap left after Ollama Cloud support landed. The rest was the previous day's routine daily update.

## What shipped

### [#1770 chore(daily): 2026-11-18 daily update](https://github.com/allenhutchison/obsidian-gemini/pull/1770)

The routine daily-update run. It added the November 17 changelog, which covers #1763 and #1765. It also fixed the "Model discovery" note in `docs/reference/provider-capabilities.md`. Since #1765, an `https://ollama.com` endpoint with an API key lists its hosted models, so cloud models no longer have to be pulled locally first. Triage found no unlabeled issues.

### [#1769 Scan nested object types for unread fields](https://github.com/allenhutchison/obsidian-gemini/pull/1769)

`scripts/check-unread-fields.mjs` used to check only top-level interface members and bare type-literal aliases. It now also collects fields from object types nested inside an interface or alias: member types, array elements, method or hook parameters, and union or intersection aliases. Nested fields are reported as `Owner.path.field`, and `wiring:keep` still suppresses them. The scan now covers 960 fields instead of 868. Closes #1758.

The PR also cleaned up what the wider scan found. `AgentLoopHooks.onBudgetUpdate` now passes only `{ remaining }`. `toolCount` was dropped from the `toolChainComplete` event. Two unread OpenRouter response declarations were removed, and Ollama's `details.family` and `details.families` are marked `wiring:keep` because they are part of the wire shape. One candidate is still reported, `AgentEventMap.turnEnd.toolCallCount`. It is deliberately left for a follow-up, because removing it means removing the whole `onToolCounted` counter chain.

### [#1767 fix(ollama): key the /api/ps context-length cache by API key](https://github.com/allenhutchison/obsidian-gemini/pull/1767)

This is a follow-up to #1765 that carries over its last unaddressed CodeRabbit finding. The `/api/ps` runtime context-length cache and its in-flight map were keyed only by endpoint and model. As a result, right after an Ollama API key change, a lookup could reuse the old key's value for up to 5 seconds, or for as long as a pending probe ran. Both are now keyed by endpoint, model and credential, the same as the `/api/show` cache, and the probe uses the same captured key. There is no user-facing change. Refs #1764.
