## What shipped

### [#1538 refactor(api): share one tool-id ledger across OpenAI and Anthropic clients](https://github.com/allenhutchison/obsidian-gemini/pull/1538)

Extracts the tool-call/tool-result id-pairing policy — validate inbound ids, mint ids the target API accepts, pair each response with the oldest unanswered call of the same tool name, report "no match" for a response whose call was compacted away — into one shared leaf module, `src/api/providers/tool-id-ledger.ts`. The policy had been implemented twice, once per provider, and had already diverged on id validation, unmatched-response handling, and part ordering; all three forks are now resolved to one behavior.

### [#1543 refactor(services): make FolderInitializer the sole creator of Scheduled-Tasks](https://github.com/allenhutchison/obsidian-gemini/pull/1543)

`Scheduled-Tasks/` and `Scheduled-Tasks/Runs/` were created twice — once by `FolderInitializer`'s eager pass and once by `ScheduledTaskManager.initialize()`'s own folder-creation calls, kept to cover a re-init ordering gap. Hoists the folder-creation call earlier in `LifecycleService.setup()` (layout-gated, idempotent) and removes the manager's duplicate creation, making `FolderInitializer` the folder's single owner. `HookManager` keeps its own creation deliberately, since `Hooks/` is gated on `hooksEnabled` and isn't eager.

### [#1544 refactor(services): give the cached-model-list lifecycle a single home](https://github.com/allenhutchison/obsidian-gemini/pull/1544)

`OllamaModelsService` and `OpenAIModelsService` each hand-wrote the same cached-fetch policy (fetch → cache keyed by endpoint identity → on failure, serve the previous cache only while identity still matches). Extracts it into a new leaf module, `src/services/remote-model-catalog.ts`, that both services now hold via composition. No behavior change, including the endpoint-identity divergence between the two providers (Ollama by base URL, OpenAI by base URL + API key) — that stays a parameter of one policy instead of two.

### [#1546 i18n: route the remaining provider attachment errors through t()](https://github.com/allenhutchison/obsidian-gemini/pull/1546)

### [#1548 build(lint): catch the hoisted form of hand-rolled path containment](https://github.com/allenhutchison/obsidian-gemini/pull/1548)

The repo's `PATH_CONTAINMENT_RULE` ESLint rule only caught `folder + '/'` when inlined directly into `.startsWith()`; hoisting it into a local variable one line earlier evaded the selector entirely, and three such sites had already landed on `master` with lint green. Adds a second selector matching the hoisted assignment shape itself. Measured against `src/`: zero current matches, since the three sites that motivated this were already fixed by a prior PR — this closes the gap for the next occurrence.

### [#1550 refactor: delete eight exports with no production caller](https://github.com/allenhutchison/obsidian-gemini/pull/1550)

Deletes eight exports identified as having zero production callers, kept alive only by test imports (invisible to `npm run knip`, whose entry points include test files). The sharpest one, `resolvePermission`, resolved a tool permission from the global policy only, ignoring per-feature policy narrowing — a footgun sitting directly beside the four-level `resolveEffectivePermission` production actually uses. Its test assertions are ported onto the real function rather than dropped.

### [#1553 fix(lifecycle): refresh task/hook managers on historyFolder rename](https://github.com/allenhutchison/obsidian-gemini/pull/1553)

A `historyFolder`-only settings save never re-ran plugin setup, since nothing snapshotted the setting for change detection — the scheduled-task and hook managers kept pointing at the old folder paths until some unrelated setting happened to change too. Adds a `previousHistoryFolder` snapshot and includes the rename in `setup()`'s entry condition, reusing the existing refresh machinery (and benefiting from #1543's folder-creation ordering).

### [#1555 fix(lifecycle): gate re-init conditions on successful initialization](https://github.com/allenhutchison/obsidian-gemini/pull/1555)

Found via review of #1553: on a vault that had never initialized successfully (e.g. missing credentials), every `previous*` baseline stayed at its default, so every settings save looked like a real change and re-ran a `setup()` doomed to fail the same way again — an error and a notice on every unrelated save. Gates each change condition on `isGeminiInitialized`, so recovery still happens the moment initialization becomes possible, but unrelated saves on a broken vault are now a no-op.

### [#1556 docs(guidelines): require a guard at every call site of the operation](https://github.com/allenhutchison/obsidian-gemini/pull/1556)

Adds a coding-guideline rule for a recurring defect shape: a guard or settings gate lands at one call site of a shared operation and is silently missing at its siblings, invisible to lint, knip, and the test suite alike. Three instances of this shape landed in the past 90 days. Prose-only — the guidelines document the pattern; there's no lint-rule shape for "every caller of X also reads setting Y" in this repo's toolchain yet.

### [#1557 refactor(models): drop the pre-redesign fallback in getActiveChatModel](https://github.com/allenhutchison/obsidian-gemini/pull/1557)

Removes `legacyActiveChatModel`, a private fallback resolver reproducing the pre-settings-redesign model shape, whose own doc comment said it was never exercised outside test fixtures. Re-verified the safety argument directly: `settings.features` is non-optional, always populated by `sanitizeFeatureRoutes` during `loadSettings`, so no production caller could ever hit the branch. Seven test fixtures were migrated to exercise the real resolution path instead.

### [#1558 fix(ollama): key showCache by endpoint and guard its write with a generation](https://github.com/allenhutchison/obsidian-gemini/pull/1558)

`OllamaModelsService.probeModel()` cached `/api/show` responses keyed by model name alone, with no generation check on the write. A probe in flight across an endpoint switch could land after the cache was cleared and re-seed it under the bare name, so a same-named model on a different daemon showed the _previous_ daemon's vision/context-window capabilities. Keys the cache by endpoint (matching the sibling `psCache`) and guards the write with a generation counter, split from `psCache`'s generation since the two caches clear on different triggers.

### [#1560 chore: remove OpenAI subscription placeholder](https://github.com/allenhutchison/obsidian-gemini/pull/1560)

Removes the disabled ChatGPT-subscription sign-in row from the OpenAI provider settings card — it advertised an authentication path not officially available for a distributed mobile app. The supported API-key and custom-base-URL controls are unchanged; tracked for possible future support in #1559.
