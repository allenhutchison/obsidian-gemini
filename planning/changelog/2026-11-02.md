## Summary

Small, internal day: a fix to how not-found errors are classified in the RAG scanner, a DRY refactor that gives the file-backed feature manager a single definition-file predicate, and the previous day's changelog and docs-audit PR.

## What shipped

### [#1720 fix(errors): detect a 404 reported as a status code or mixed-case phrase](https://github.com/allenhutchison/obsidian-gemini/pull/1720)

`isNotFoundError` matched only case-sensitive message substrings, so a 404 carried on the error object (for example `status: 404` with a generic message) or the mixed-case phrase `Not Found` was missed. It now consults `extractStatusCode` first and folds case before matching. `RagVaultScanner` uses the predicate to decide whether a File Search store must be recreated, so a missed 404 turned a recoverable case into a hard failure. Regression tests were added and the scanner's `isNotFoundError` mock was brought in line.

### [#1722 refactor(services): give FileBackedFeatureManager the definition-file predicate](https://github.com/allenhutchison/obsidian-gemini/pull/1722)

The "is this one of my definition files?" check was written three times (the base manager's discovery filter and two `ScheduledTaskManager` event handlers). `FileBackedFeatureManager` now owns it through `definitionPathFilter()` (a hoisted closure for the vault-wide discovery filter) and `isDefinitionFile(file)` (adds the markdown check for event handlers). Pure refactor with no behaviour change.
