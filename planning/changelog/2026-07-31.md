### [#1286 feat: OpenAI-compatible provider with API key auth](https://github.com/allenhutchison/obsidian-gemini/pull/1286)

Adds a third model provider, `openai`, alongside Gemini and Ollama — closing #1237. Talks to the OpenAI Chat Completions API with the user's own API key; because the base URL is configurable, it equally serves OpenAI-compatible runtimes like LM Studio or Ollama's OpenAI-compatible endpoint. Includes streaming with cancellation, agent tool calling, image attachments on vision models, per-use-case model settings, and a model-discovery service that enriches known OpenAI models with curated metadata. Web search, RAG, and image generation remain Gemini-only.

Explicitly out of scope: ChatGPT-subscription ("Sign in with ChatGPT") auth — this provider is API-key billing only.

### [#1288 fix(openai): make the GPT-5.6 models usable — unblock 400s, trim the catalog, fix context windows](https://github.com/allenhutchison/obsidian-gemini/pull/1288)

Same-day follow-up to #1286: the merged OpenAI provider couldn't complete a single request against `api.openai.com`'s GPT-5.6 models — every chat turn 400'd, because the client always sent `temperature`/`top_p` (which these reasoning models reject) and the API rejects function tools for them unless `reasoning_effort` is `'none'`. Also narrows the hosted model dropdowns from ~90 mostly-undrivable ids to an allowlist of three, corrects their context windows to a measured 922,000 tokens (curated values were wrong for all three), and fixes the context manager to read a model's own window for any provider instead of falling back to the flat provider default — previously only Ollama got per-model windows, so OpenAI's `contextWindow` was dead data and history compacted at ~14% of real capacity.

### [#1287 refactor(context-manager): make chars-per-token calibration provider-neutral](https://github.com/allenhutchison/obsidian-gemini/pull/1287)

The local chars-per-token calibration path in `ContextManager` was named for Ollama throughout, but it's a generic fallback for any provider without a `nativeTokenCount` — now including OpenAI. Renamed the identifiers and updated doc comments and debug logging to stop claiming Ollama; behavior is unchanged. The genuinely Ollama-specific context-window resolution path (runtime-allocation lookup via `/api/ps`) keeps its Ollama naming.
