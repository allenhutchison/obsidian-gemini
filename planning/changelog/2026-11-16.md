## Summary

A bugfix-heavy day. The largest merge fixes four filed bugs in one PR: pre-flight request errors no longer retry, completions stop inserting a space mid-word, `countTokens` no longer fails on histories that end on a model turn, and provider dispatch is now exhaustive at compile time. Manual testing of that PR turned up a provider-status bug, fixed the same evening. The GPT-6 / GPT-6.1 models were added to the OpenAI allowlist. Two Dependabot bumps and the routine daily-update PR round out the day.

## What shipped

### [#1759 chore(daily): 2026-11-16 daily update](https://github.com/allenhutchison/obsidian-gemini/pull/1759)

Daily-update run that added `planning/changelog/2026-11-15.md` and fixed three doc spots left stale by #1754's move to runtime Gemini model discovery (`docs/guide/completions.md`, `docs/guide/faq.md`, `docs/reference/settings.md`). The settings reference no longer says Model Discovery runs in the background, since startup now waits for it. Triage found no unlabeled issues.

### [#1760 Fix four new bugs: retry fast-fail, mid-word completions, countTokens 400, provider fall-through](https://github.com/allenhutchison/obsidian-gemini/pull/1760)

One commit per issue. For #1738, a new `NonRetryableRequestError` marks client-side checks that fail before any request is sent (no model selected, unsupported attachment), so a PDF sent to OpenAI or OpenRouter now errors at once instead of after about 8s of backoff. For #1739, the completions prompt and `joinCompletion()` now continue the current word when the cursor is mid-word instead of always adding a space. For #1708, a minimal synthetic user turn is appended before native `countTokens` when history ends on a model turn, and a failed count falls back to a character estimate instead of `0`.

For #1757, provider dispatch in the factory, `apiKeySecretNameFor`, `getProviderModelsService` and the credential and base-URL lookups in `main.ts` is now a `switch` or a `Record<ModelProvider, …>`, so a missing provider is a compile error. Ollama no longer gets Gemini's secret name. This removed nine `no-restricted-syntax` disables, and the invariant is now written down in `.claude/guidelines/invariants.md`. The `countTokens` fix has not been run against live `gemini-4-argon`.

### [#1761 Show provider cards as Connected only when the key actually resolves](https://github.com/allenhutchison/obsidian-gemini/pull/1761)

Found during manual vault testing of #1760. `providerConnection()` checked only that a secret name was saved, so the OpenRouter card said Connected while its secret was empty, even though the Features page said it was not connected. It now returns `needs-key` for any provider that needs a key unless the saved name resolves to one. A custom OpenAI-compatible endpoint, where a key is optional, is unchanged. `featureStatus` drops its separate key check, and the card label and both warnings now agree with the Features page. `docs/reference/settings.md` explains when a card shows Connected.

### [#1762 Offer GPT-6 / GPT-6.1 models on api.openai.com](https://github.com/allenhutchison/obsidian-gemini/pull/1762)

Part (a) of #1755. `gpt-6-sol`, `gpt-6-luna`, `gpt-6-astra`, `gpt-6.1-sol` and `gpt-6.1-terra` join the api.openai.com allowlist. None of them becomes a role default, and no context window is declared yet. `gpt-6-sol` and `gpt-6-luna` send tools with `reasoning_effort: 'none'`, like GPT-5.6. `gpt-6.1-*` and `gpt-6-astra` reject tools on Chat Completions, so their requests go out without tools and log a warning. `docs/guide/openai-setup.md` gained a "GPT-6 limitations" section saying the agent has no vault tools on those models. Part (b), a Responses API path for full tool calling, is #1763, stacked on this PR. Not verified live.
