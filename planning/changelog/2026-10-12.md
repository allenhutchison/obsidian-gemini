### [#1653 Add searchable model picker for long model lists](https://github.com/allenhutchison/obsidian-gemini/pull/1653)

Replaces the native model dropdowns on the Features page and in the session settings modal with a shared fuzzy-search picker (`ModelPickerModal`), so a model can be found by typing part of its name or id. This came out of discussion #1649, where an OpenRouter key through the OpenAI provider lists 458 models in API order. Sorting is display-only and lives in the picker, not the provider model services, because `getDefaultModelForRole` falls back to the first listed model and sorting the catalogs would change which model an empty "Default" route resolves to. A side effect is that the Gemini and Anthropic lists now appear alphabetically. Guides and the settings reference were updated.

### [#1656 Validate headless output paths and return the written path](https://github.com/allenhutchison/obsidian-gemini/pull/1656)

Routes the hook and scheduled-task output pipeline through `validateGeneratedOutputPath()`, so an `outputPath` can no longer write into `.obsidian` or among the plugin's own state (the only carve-outs are `Hooks/Runs/` and `Scheduled-Tasks/Runs/`). Paths are validated before the model turn, and the management modals check at save time. Behaviour change: a stored `outputPath` that is now refused fails the run, records the reason as the last error, and writes nothing. The same PR fixes both runners returning the resolved base path rather than the path actually written, which made "Open result" on a repeat same-day run point at the earlier note. Fixes #1651.
