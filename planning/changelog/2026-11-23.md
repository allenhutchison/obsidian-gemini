# Daily changelog — November 23, 2026

**Date:** 2026-11-23
**PRs merged:** 13

---

## Summary

The day after 4.14.0 was a heavy cleanup day. The one user-facing feature was #1796: each chat session can now pin its own provider in Session settings. Its author expects it to make the next release 4.15. #1805 added the GPT-6.2 and Images 2.6 models and gave the GPT-6 family a real 922k input limit. #1794 fixed the token count jumping back up after compaction. The rest were refactors with no behaviour change, most of them closing small architecture issues, plus a large batch of new modal tests (#1813). Two of the PRs came from the nightly `audit-architecture` sweep (#1798, #1803).

## What shipped

### [#1804 chore(daily): 2026-11-23 daily update](https://github.com/allenhutchison/obsidian-gemini/pull/1804)

The scheduled daily-update run. It added the November 22 changelog. The docs audit found no drift, and triage found no unlabeled issues.

### [#1803 docs(agent-view): put the turnHandle doc back on turnHandle](https://github.com/allenhutchison/obsidian-gemini/pull/1803)

A fix found by the `audit-architecture` sweep. #1792 left the JSDoc for `turnHandle` sitting above `hideProgressFor` in `AgentViewSend`, so the per-turn handle behind the Stop fix had no doc and the wrong method had two. The comment is now on the right method. Comment-only.

### [#1798 refactor(ollama): share the keyless-cloud-endpoint predicate](https://github.com/allenhutchison/obsidian-gemini/pull/1798)

Another `audit-architecture` finding. The check "this request would go to ollama.com without the key it requires" was written out at four call sites. It is now one function, `missingOllamaCloudKey(baseUrl, apiKey)`, in the Ollama config module. Each caller still passes its own base URL, so the runtime context-length probe keeps testing the resolved cloud endpoint. No behaviour change. The similar two-site OpenAI check was left alone on purpose.

### [#1805 Add GPT-6.2 and Images 2.6 models, set GPT-6 input limit](https://github.com/allenhutchison/obsidian-gemini/pull/1805)

Updates the api.openai.com catalog (#1797). The GPT-6, 6.1 and 6.2 models now declare a 922,000-token input limit. Before, they fell back to 128k, so the token counter turned red and compaction started around 100k. `gpt-6.2-sol` and `gpt-6.2-astra` are added, and their agent turns go through the Responses API like `gpt-6.1-*`. `gpt-image-2.6-flare` and `gpt-image-2.6-sunburst` are offered for image generation, and `gpt-image-2.5-flare` stays the default.

The 922k figure comes from OpenAI's published model cards and hasn't been measured against the live API. A live OpenAI test was still pending when it merged.

### [#1793 Track an indexing run's progress in one holder (#1703)](https://github.com/allenhutchison/obsidian-gemini/pull/1793)

Refactor with no behaviour change. An indexing run's progress used to be eight separate fields on `RagVaultScanner`. It now lives in one `IndexRunProgress` holder in the new `src/services/rag-run-progress.ts`. Three hand-copied reset sites become named methods, and six pass-through getters become a single `getRunProgress()` snapshot.

### [#1794 Let prepareHistory own the token-usage cache after compaction (#1699)](https://github.com/allenhutchison/obsidian-gemini/pull/1794)

Fixes the token count that dropped after compaction and then jumped back up. `prepareHistory` now updates the cached usage itself through a new `ContextManager.reviseCachedEstimate`, which keeps the cached-prefix and reasoning figures and lets the next real report replace the estimate. The force-sets in `AgentLoop` and `AgentViewSend` are removed. Switching sessions still replaces the cache completely, so one session's figures don't carry into the next.

### [#1795 Gate the maps tool on the registry's maps capability (#1701)](https://github.com/allenhutchison/obsidian-gemini/pull/1795)

The Google Maps tool used to be offered when a Gemini key was present. It now asks the provider registry whether some provider with the `maps` capability has a usable key, through a new `providerBoundAvailable` helper. Today that is still only Gemini, so nothing changes yet, but changing the capability flag in `registry.ts` now moves the tool gate too.

### [#1796 Add a per-session provider picker to session settings (#1679)](https://github.com/allenhutchison/obsidian-gemini/pull/1796)

New feature: a chat session can use a different provider from the Chat route, for example one conversation on Claude while Chat goes to Gemini. Session settings gain a **Provider** dropdown above Model. It lists "Use default" and each connected provider that can chat. Changing it clears the session's model. The choice is saved as `provider` in the session frontmatter.

The factory builds the chosen provider's client, or fails with `FeatureUnavailableError` if that provider can't chat. It never falls back to another provider. Only chat moves: web search, deep research and image generation keep their own routes. The header badge now also appears for a provider override. The agent-mode guide and the settings reference were updated. A desktop test was still pending when it merged.

### [#1808 Share one notice policy between attachment drop and paste](https://github.com/allenhutchison/obsidian-gemini/pull/1808)

Dropping and pasting images had separate notice code that had drifted apart. For example, pasting an image in an unsupported format didn't say which formats work. Both now call one `notifyAttachmentOutcome` helper, so the same result gives the same notice. The paste-only string key was retired and removed from each locale file (#1799).

### [#1809 Make tool schemas always carry required, and drop the mapper fallbacks](https://github.com/allenhutchison/obsidian-gemini/pull/1809)

`required` is now mandatory on both tool schema types (#1801). The `?? []` fallbacks in five provider mappers and the prompt builder could no longer trigger and were deleted. The compiler found no production code that omitted the field, only three test fixtures. The tool-development contributing guide was updated. No behaviour change.

### [#1810 Wire Enter/Space activation through one helper](https://github.com/allenhutchison/obsidian-gemini/pull/1810)

The "activate on click, Enter or Space" listener code was copied in four places. It now lives in one `wireActivation` helper in the new `src/ui/components/activatable.ts` (#1800). The agent-view progress block uses it with a gate, and the context shelf keeps its own handler because it also handles Delete, Backspace and the arrow keys. Markup, roles and ARIA are unchanged. The UI guidelines skill gained a "Keyboard Activation" rule.

### [#1811 Move failure-tracker wiring into FileBackedFeatureManager](https://github.com/allenhutchison/obsidian-gemini/pull/1811)

`HookManager` and `ScheduledTaskManager` each set up the same `FailurePauseTracker` by hand. That setup is now one `createFailureTracker()` method on the shared `FileBackedFeatureManager` base class (#1802), and its log label comes from the manager's existing log prefix. No behaviour change.

### [#1813 Add decision-surface tests for the DOM-heavy modals](https://github.com/allenhutchison/obsidian-gemini/pull/1813)

Test-only (#1596). It adds 62 tests across the background tasks, MCP server, rewrite and scheduler management modals. The tests check what each modal decides, such as save payloads, validation, the actions a row offers, and listener teardown, rather than its markup. A new `test/ui/obsidian-dom.ts` helper adds Obsidian's element-factory methods to jsdom so modals render into a real DOM. Tests for the hook management modal are in #1812, which was still open.
