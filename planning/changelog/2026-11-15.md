## Summary

The day's one substantive change is a provider-architecture change. Gemini now discovers its models at runtime through Google's ListModels API, the same way every other provider already did. The bundled `models.json`, its update script and its weekly refresh workflow are gone. The other merge was the routine daily-update PR.

### [#1754 Discover Gemini models at runtime like every other provider](https://github.com/allenhutchison/obsidian-gemini/pull/1754)

Gemini was the only provider whose model list shipped with the plugin. That list was a bundled `models.json`, re-downloaded every 24 hours and kept current by a weekly workflow that opened a PR for each new model. A new `GeminiModelsService`, built on the shared `CachedModelCatalog`, now queries ListModels with the user's key, so a new Gemini model needs no code change. The filtering rules from the old update script moved into `src/api/providers/gemini/model-catalog.ts`. They now also exclude the video-only Omni models, which resolves the main part of #1707. When the API can't be reached, the plugin uses the last list it fetched, or a four-entry built-in fallback if it has never fetched one.

Stale-model reconciliation now runs only against providers whose last probe succeeded, so a fallback list can't reset a saved model choice. The PR removed `src/data/models.json`, `scripts/update-models.mjs`, `.github/workflows/model-update.yml` and `ModelListProvider`. When Gemini is the active provider, startup now waits for one ListModels call. Whether to delete the leftover `interactionsOnly` routing is still open on #1707.
