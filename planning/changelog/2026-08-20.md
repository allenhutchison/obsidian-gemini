## What shipped

### [#1371 fix(vault-analyzer): exclude plugin state files from the vault fingerprint](https://github.com/allenhutchison/obsidian-gemini/pull/1371)

`collectVaultInformation()` was counting the plugin's own `Agent-Sessions/`, `Prompts/`, and `Scheduled-Tasks/` notes toward the vault's markdown file count, inflating the number the model reasons about. Worse, the large-vault cache fingerprints on the newest file `mtime`, and the plugin rewrites its session file on every agent turn — so the cache was invalidated by the plugin's own writes and never actually hit during a chat session. Fixed with a shared `excludeSystemFiles()` helper applied before both the count and the fingerprint are derived.

### [#1372 fix(vault): use root-anchored containment for two folder checks](https://github.com/allenhutchison/obsidian-gemini/pull/1372)

`PromptManager.listAvailablePrompts()` and `SessionManager.loadSessionFromFile()` used a bare `String.startsWith()` instead of the repo's `isPathInFolder()` helper, so a sibling folder or file with a matching name prefix (e.g. `Prompts-archive/`, `Agent-Sessions-archive/`) was misclassified — extra files listed as custom prompts, or a session file typed `AGENT_SESSION` instead of `NOTE_CHAT`. Both sites now route through the shared helper; regression tests cover both over-match cases.

### [#1366 refactor(utils): reuse moveCursorToEnd in insertTextAtCursor](https://github.com/allenhutchison/obsidian-gemini/pull/1366)

`insertTextAtCursor` inlined the same five-call cursor-collapse-to-end sequence twice instead of calling the existing `moveCursorToEnd` helper a few lines below. Mechanical dedup, no behavior change.

### [#1367 refactor(rag): build the empty index cache in one place](https://github.com/allenhutchison/obsidian-gemini/pull/1367)

`loadCache` constructed the same empty `RagIndexCache` literal at three separate recovery paths (version mismatch, missing file, load failure). Extracted a private `RagCache.emptyCache()` factory used at all three sites, preserving each path's existing `storeName` behavior.

### [#1368 refactor(agent): share the recent-session-file listing](https://github.com/allenhutchison/obsidian-gemini/pull/1368)

`getRecentAgentSessions` and `getSessionMetadata` each independently resolved the Agent-Sessions folder, filtered to markdown files, sorted by `mtime`, and sliced to a limit — the hydrated and frontmatter-only views of the same list. Extracted into a shared `listRecentSessionFiles()` helper so the two views can't silently drift apart.
