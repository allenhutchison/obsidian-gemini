### [#1514 refactor(hooks): route every hook field through one descriptor table](https://github.com/allenhutchison/obsidian-gemini/pull/1514)

Fixes #1315. Replaces six separate longhand field lists across `hook-manager.ts`/`hook-types.ts` with one `HOOK_FIELDS` descriptor table whose type is total over `Hook`'s keys, so an added field now fails to compile until it's described in the table — closing a bug class where a field could load from a hand-written file but silently drop on save through the UI. Also fixes the underlying merge bug: six fields (`pathGlob`, `model`, `outputPath`, `commandId`, `maxRunsPerHour`, `focusFile`) are now clearable from the edit form for the first time, and `maxRunsPerHour: 0` consistently means "no limit" rather than disagreeing between the parse and create/update paths.

### [#1518 fix(projects): drop dead wikilink resolution, make docs match behavior](https://github.com/allenhutchison/obsidian-gemini/pull/1518)

Fixes #1459. `ProjectManager.parseProjectFile` populated `Project.contextFiles`/`embedFiles` from `[[wikilinks]]`/`![[embeds]]` in project files, but no production code ever read either field — so a user who wrote a wikilink under "Additional Context" got only the literal link text in the prompt, not the resolved reference the docs promised. Per the maintainer's "make the code true" call, this deletes the dead resolution code and rewrites `docs/guide/projects.md` to state that links are passed through as instructions text, followable via tools like `read_file`.

### [#1519 refactor(agent): delete unwired onEmptyResponseRetry hook](https://github.com/allenhutchison/obsidian-gemini/pull/1519)

Fixes #1502. Removes `AgentLoopHooks.onEmptyResponseRetry`, which no production caller ever supplied — the fifth instance of this pattern (following #1436, #1457, #1458, #1467), all resolved the same way per the "wiring interfaces carry only what is read" guideline. No behavior change.

### [#1520 fix(projects): make project root a hard scope for all discovery tools](https://github.com/allenhutchison/obsidian-gemini/pull/1520)

Fixes #1506. The four discovery tools disagreed on project-root enforcement: `find_files_by_name`/`find_files_by_content` hard-filtered to the project root, while `list_files`/`vault_semantic_search` treated it only as a default that a model argument could override — so `list_files` with `path: "/"` could read the entire vault while a project was active. Adds a shared `isPathInProjectScope` predicate, gates both remaining tools on it with an explicit out-of-bounds error, and threads a scope statement into the system prompt so the model knows the boundary exists. Known behavior change: agents that previously reached outside a project through these two tools' arguments now get an error instead of silent results.

### [#1521 refactor(api): share the Gemini-Content history walk across provider clients](https://github.com/allenhutchison/obsidian-gemini/pull/1521)

Fixes #1373. `OllamaClient` and `OpenAIClient` each independently decoded the same two conversation-history shapes (Gemini `Content` and the legacy `{ role, text | message }` entry) before emitting their own provider message type. Extracts the shared decoding into a new leaf module, `src/api/providers/history-walk.ts` (`walkHistoryEntry()`), used by both clients as thin adapters; each client keeps only its genuinely provider-specific ordering and id-matching logic. No observable behavior change, verified by mutation testing the new walker.
