### [#1812 Add an agent-turn-ended hook trigger](https://github.com/allenhutchison/obsidian-gemini/pull/1812)

Adds `trigger: agent-turn-ended`, which fires once each time the agent finishes responding in the agent chat (issue #1806). The two cases it was built for are a `command` hook that runs `obsidian-git:commit` to commit the agent's edits as you go, and an `agent-task` hook that keeps a turn log. One commit can cover several turns: turns that end inside the debounce window share one run, and a turn that ends during the cooldown is skipped. The `turnEnd` event now carries an outcome (`complete`, `incomplete`, `failed` or `cancelled`) and the user's message. The tool loop reports the outcomes it used to swallow, such as the iteration cap and the loop-detector abort, and Stop takes precedence. Turn fires go through the same gates, cooldown, debounce, loop ceiling and rate limit as file hooks. Debounced turns are merged, and headless sessions never fire. The trigger only allows the agent-task and command actions. Hook prompts get new variables: `{{turnOutcome}}`, `{{turnCount}}`, `{{toolCallCount}}`, `{{sessionTitle}}` and `{{userMessage}}`. The hook editor narrows its fields when the trigger is chosen and warns about cost for agent-task hooks.

It was built in a cloud session, so a desktop check of the hook editor was still pending when it merged. The lifecycle hooks guide and README cover the new trigger.
