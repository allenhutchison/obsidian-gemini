## Summary

Also landed a translation-model housekeeping fix, a dependency security cleanup, the previous day's automated daily update, and two Dependabot bumps.

## What shipped

### [#1508 Redesign settings: feature routing table and provider connection cards](https://github.com/allenhutchison/obsidian-gemini/pull/1508)

Rebuilds the settings tab on Obsidian 1.13's declarative settings API. A Providers page now shows one connection card per account or endpoint (Gemini, Ollama, OpenAI, plus an Anthropic placeholder); a Features page shows one row per feature as "provider · model," with a feature that can't be served by its provider staying off with a warning rather than silently rerouting. Top-level settings drop from roughly 17 always-visible rows to 13 rows across five groups, with less-common settings moved to sub-pages. Several settings were removed outright (streaming toggle, Interactions API toggle, temperature/top-p, retry/backoff knobs, loop-detection knobs, per-feature provider grouping, MCP enable toggle), and the underlying data model changes to `settings.features: Record<FeatureId, {provider, model}>` with automatic one-way migration. This is a breaking release — `minAppVersion` moves to 1.13.1.

### [#1509 Default the translation script to gemini-flash-latest](https://github.com/allenhutchison/obsidian-gemini/pull/1509)

Points the i18n translation script at Google's rolling `gemini-flash-latest` alias instead of a numbered Flash release, so the `Update UI translations` workflow doesn't need a manual bump every time Flash rolls a new version. `GEMINI_TRANSLATE_MODEL` and `--model` still override the default; the eval judge and pricing table keep their pinned versions.

### [#1510 Resolve Dependabot alerts for ip-address and vite](https://github.com/allenhutchison/obsidian-gemini/pull/1510)

Clears all six open Dependabot alerts (2 high, 4 moderate) plus two further `npm audit` findings, bringing `npm audit` to zero vulnerabilities. `ip-address` (via the MCP SDK's `express-rate-limit`) gets a lockfile update to a patched release; `vite` (via `vitepress`) gets constrained to `^6.4.3` through a package.json `overrides` entry, since no vite 5 release carries the fix and vitepress 2.0 is still alpha. All affected packages are dev-time only — nothing ships in `main.js`.
