# Daily changelog — October 17, 2026

**Date:** 2026-10-17
**PRs merged:** 10

---

## Summary

Version 4.13.0 shipped, led by reliable `@` and `/` pickers on Android and a new skill button in the agent input. Two small input fixes (pasted newlines, selectable response text) and a settings type fix landed alongside routine dependency and translation updates.

## What shipped

### [#1667 fix: Allow selecting text in the selection response modal](https://github.com/allenhutchison/obsidian-gemini/pull/1667)

The response modal behind "Ask question..." and "Apply prompt..." inherited Obsidian's `user-select: none`, so only the Copy button worked. Text selection is re-enabled on the response container and the selected-text preview, and `docs/guide/ai-writing.md` notes it. Closes #1664.

### [#1668 chore(daily): 2026-10-17 daily update](https://github.com/allenhutchison/obsidian-gemini/pull/1668)

Adds the October 16 changelog. The docs audit and triage had nothing further to change.

### [#1666 chore(i18n): Update UI translations](https://github.com/allenhutchison/obsidian-gemini/pull/1666)

Automated regeneration of `src/i18n/` from the current English source strings.

### [#1670 fix: Preserve newlines when pasting into the agent input](https://github.com/allenhutchison/obsidian-gemini/pull/1670)

Pasted multi-line text collapsed onto one line, both on screen and in the message actually sent, because the input had the default `white-space: normal`. The input now uses `white-space: pre-wrap`, guarded by a stylesheet regression test. Fixes #1669.

### [#1671 fix(agent-view): reliable @ and / pickers on Android, plus a skill button](https://github.com/allenhutchison/obsidian-gemini/pull/1671)

Android keyboards send `key: 'Unidentified'` on keydown, so the `@` and `/` pickers never opened. Trigger detection moved to the `input` event, which also works on iOS and physical keyboards. A new wand button next to Send opens the skill picker and places the `/skill-name` token at the start of the message. Refs #1661, which stays open for the sidebar-overlap re-test.

This release was cut the same evening as 4.13.0 (direct release commits, not PRs).

### [#1673 chore(deps): bump the production-dependencies group](https://github.com/allenhutchison/obsidian-gemini/pull/1673)

Dependency bumps: `@anthropic-ai/sdk` 0.132.0 to 0.134.0 and `openai`.

### [#1676 fix(agent-view): ignore plain input events in the picker trigger](https://github.com/allenhutchison/obsidian-gemini/pull/1676)

Follow-up hardening for #1671: a plain `Event('input')` dispatched by another plugin threw `instanceOf is not a function`, since Obsidian only adds `instanceOf` to `UIEvent`. The handler now checks the method exists first. Fixes #1675.

### [#1672 chore(i18n): Update UI translations](https://github.com/allenhutchison/obsidian-gemini/pull/1672)

Automated translation regeneration for the new skill button strings.

### [#1677 fix(settings): store a cleared API key picker as '' instead of null](https://github.com/allenhutchison/obsidian-gemini/pull/1677)

Obsidian 1.14 types `SecretComponent.onChange` as `string | null`. Clearing the picker could store `null` in the `apiKeySecretName` settings; it now stores `''`, the existing "no key" default. This unblocked #1674.

### [#1674 chore(deps-dev): bump the dev-dependencies group](https://github.com/allenhutchison/obsidian-gemini/pull/1674)

Ten dev-dependency updates, including `obsidian` 1.13.1 to 1.14.4, `@google/genai` 2.28.0 to 2.30.0 (adds `gemini-4-argon` to its Model enum), vitest 5.0.4 and knip 6.41.0.
